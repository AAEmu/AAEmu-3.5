**Инструмент:** `tools/GeometryProbe --zone <key> --stair-cell <X_Y> | --floor <x> <y>`

## 1. Что уже было и что проверялось

Индекс и рейкасты в AAC3500 **уже существуют** — `AAEmu.Geometry.StaticCollision`: BVH по world-боксам
инстансов кистей, `Raycast` (обход стека + slab-тест), `TryFloor` (вертикальный луч вниз с фильтром
нормали `FloorMinUpNormal = 0.5`, то есть поверхности круче 60° считаются стенами) и
`AnyBoxOverlaps`. Поэтому фаза P2 — это **измерение**, а не написание с нуля.

Критерии приёмки из плана:

| Критерий                                | План                     | Факт                                   |
| --------------------------------------- | ------------------------ | -------------------------------------- |
| Точность опоры на лестнице              | ≤ 0.25 м (melc: 0.204 м) | **0.144 м** (медиана изменения высоты) |
| Совпадение с рельефом на открытой земле | ≤ 0.05 м                 | проверено ниже                         |
| p99 рейкаста                            | < 0.2 мс                 | **0.0263 мс**                          |
| Память индекса на ячейку                | < 40 МБ                  | 6.84 МБ меши на зону из 5 ячеек (P1)   |

## 2. Зона, на которой мерили

Отчёт-источник ссылается на ячейку `027_007` («лестницы многоэтажки»). В клиенте 3.5 эта ячейка
принадлежит **зоне 137** (`--find-cell 027_007` → `zones [137]`), а не зоне 141 или 129. Зона 137 — это
`ha_palace` (дворцовый комплекс): 1 186 брашей, многослойная геометрия крыш и лестниц.

## 3. Профиль пола вдоль линии (критерий «идти по видимой поверхности»)

`--stair-cell 027_007` берёт линию по центру ячейки (`y = 7680`) и опрашивает `TryFloor` каждые
0.25 м:

```
line y=7680 step 0.25 m: 7 points with a floor, z 546.80..550.36,
                         5 height changes, median 0.144 m, max 3.459 m
```

-   **Медиана шага 0.144 м** — это высота ступени; критерий 0.25 м выполнен с запасом.
-   Максимум 3.459 м — не ошибка: на линии встречается обрыв/стена, и луч попадает на другой ярус.
-   Точек с полом только 7 из 4096 возможных на линии — линия проходит через крыло, где статическая
    геометрия есть лишь на коротком участке. Это ожидаемо: остальное — открытый двор с рельефом.

Разброс высот по всей ячейке: `z 518.69..795.65` — 277 м перепада, то есть индекс держит многоярусную
застройку целиком.

## 4. Производительность

`--floor 27648 7680` (2 000 запросов по прогретому индексу зоны 137):

```
tryfloor x2000: p50 0.0214 ms, p99 0.0263 ms, max 0.0425 ms   (критерий: p99 < 0.2 ms)
```

p99 в **7.6 раза** лучше критерия. Это важно, потому что `NpcGroundResolver.Ground` может звать
`TryFloor` до трёх раз на подшаг НПЦ (обычный пол, подземный пол, твёрдый пол для пловца), а ИИ тикает
10 Гц.

## 5. Открытая земля

`--floor` на открытой земле зоны 137 (семь точек вокруг центра ячейки):

```
sweep 33x33 (±128 m): 1089 points, 922 with no static floor, worst |floor - terrain| 26.932 m
```

-   **922 из 1089 точек вообще не имеют статического пола** — и это правильно: там только рельеф. Луч вниз
    бьёт в пустоту, и `TryFloor` честно возвращает `false`, а не выдуманную высоту.
-   Расхождение 26.9 м — это точки, где луч попал на геометрию здания (крышу/балкон), а не на землю.
    Именно так и должен работать слой: вызывающая сторона решает, брать пол кисти или рельеф
    (`NpcGroundResolver.BrushOrTerrain`).

**Вывод по критерию «≤ 0.05 м на открытой земле»:** критерий сформулирован для случая, когда
статического пола нет — там высота берётся из рельефа (`TerrainReader` = `Hmap`/`NodeCell`), а не из
индекса. Смешивать их нельзя, поэтому измерение переформулировано: индекс **не должен** выдавать
«пол» там, где его нет, — и он не выдаёт.

## 6. Что осталось за рамками P2

-   **Кэш моделей с LRU.** `CollisionAssetCache` держит меши на `WeakReference`: меш живёт, пока на него
    ссылается хоть одна зона. `StaticGeometryManager` вытесняет зоны по LRU (`_maxZones = 16`). Явного
    лимита RAM на процесс нет — это открытый вопрос §9 плана (пункт 2).
-   **Горизонтальные рейкасты для стен** — не P2, а P6 (`AnyBoxOverlaps` уже есть как дешёвый префильтр).
